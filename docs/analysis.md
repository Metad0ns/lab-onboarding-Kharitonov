# Анализ legacy_calc.py

## Логика алгоритма
Функция `calc_bonus` рассчитывает бонус в зависимости от суммы продаж (x),
количества месяцев (y) и категории клиента (z).

- Если сумма продаж больше 1000, бонус начисляется помесячно: за каждый
  из y месяцев к результату прибавляется доля суммы x. Для категории 1
  это 15 %, для категории 2 это 10 %, для остальных категорий это 5 %.
- Если сумма продаж не больше 1000, категория клиента не учитывается:
  при y > 10 бонус равен x * y * 0.02, в остальных случаях x * y * 0.01.
- Накопленный результат `res` возвращается из функции.

## Выявленные недостатки (Code Smells)
1. Магические числа: 1000, 0.15, 0.10, 0.05, 10, 0.02, 0.01. Их нужно
   вынести в именованные константы.
2. Плохой нейминг: x, y, z не отражают бизнес-смысл (лучше `sales_sum`,
   `months`, `customer_category`).
3. Глубокая вложенность: цикл внутри условия внутри условия.
4. Лишний цикл: в ветке x > 1000 прибавляется одно и то же значение
   y раз, это можно заменить умножением `x * rate * y`.
5. Нет валидации входных данных: отрицательные x и y, неизвестная
   категория z молча получает ставку 5 %.
6. Денежные суммы считаются в типе float (ошибки округления).
7. Нет документации (docstring) и тестов.
