## 2. Цели ревью

1. Убедиться в корректности расчета суммы корзины и применения скидок и
   в безопасной интеграции с бэкенд-API и платежной системой.
2. Проверить производительность отрисовки компонента при большом числе
   товаров и отсутствие лишних запросов к API.
3. Проверить качество пользовательского опыта: состояния загрузки и
   ошибок, работу с пустой корзиной.

## 3. Критерии проверки (чек-лист)

### 3.1. Функциональная корректность

- [ ] Сумма корзины считается верно для 0, 1 и 100 товаров (есть unit-тесты)
- [ ] Итоговая сумма со скидками совпадает с расчетом бэкенда (расхождение 0 копеек)
- [ ] Обработаны граничные состояния: пустая корзина, товар закончился, ошибка ответа API
- [ ] Пользователь видит индикатор загрузки и понятное сообщение об ошибке

### 3.2. Безопасность / Надежность

- [ ] Итоговая сумма для оплаты проверяется на сервере, клиентскому расчету не доверяем
- [ ] В коде нет типа `any`, типы ответов API описаны (0 использований `any`)
- [ ] Платежные данные не логируются и не сохраняются в localStorage

### 3.3. Производительность

- [ ] При изменении количества одного товара перерисовывается только его строка (проверка в React Profiler)
- [ ] Отрисовка корзины из 50 товаров занимает не более 100 мс (React Profiler)
- [ ] При изменении количества отправляется не более 1 запроса к API (debounce)

### 3.4. Читаемость и стиль

- [ ] Компонент не длиннее 200 строк, логика расчета вынесена в отдельную функцию или хук
- [ ] ESLint и Prettier проходят без ошибок
- [ ] Имена переменных и функций понятны, у сложных участков есть комментарии
